# ModalChat 插件 — 事件与数据流

> 编写日期：2026年7月25日 | 最后更新：2026年7月28日

## 一、SillyTavern 事件处理

ModalChat 在 `shell/message-handler.js` 的 `registerEventListeners()` 中注册以下事件监听：

| 事件 | 用途 | 回调函数 | 处理内容 |
|------|------|---------|---------|
| `MESSAGE_RECEIVED` | AI 消息接收后触发匹配（**核心入口**） | `onMessageReceived` | 异步执行 chat-images 匹配 + match-scoring 评分，主动插入 DOM |
| `CHARACTER_MESSAGE_RENDERED` | AI 消息渲染完成后（备选触发） | `onAiMessageRendered` | 如果 `onMessageReceived` 的异步评分未完成，在此事件中补插结果 |
| `MESSAGE_SWIPED` | 滑动切换回复 | `onMessageSwiped` | 清除旧结果，检测文本是否变化，清除 chat-images 待执行定时器，如有变化则重新匹配 |
| `CHAT_CHANGED` | 切换聊天 | `onChatChanged` | 清除所有缓存、结果面板、图片定时器 |
| `CHAT_LOADED` | 聊天加载完成 | `onChatLoaded` | 恢复持久化匹配结果到聊天气泡 |
| `MESSAGE_DELETED` | 消息删除 | `onMessageDeleted` | 触发重新匹配 |

### 1.1 关键设计：异步双通道渲染 + generation 防过期

由于 `import()` 动态导入是异步的，match-scoring 的评分结果可能在 `CHARACTER_MESSAGE_RENDERED` 事件触发时尚未完成。因此采用**双通道策略**：

1. **通道 A（主动）**：`onMessageReceived` 中，评分完成后立即调用 `renderChatResults()` 插入 DOM
2. **通道 B（备选）**：`onAiMessageRendered` 中，检查 `pendingResults`，如果存在未插入的结果则补插

同时，chat-images 的 `performMatch()` 使用 `_ciGeneration` 计数器，防止滑动时陈旧异步结果覆盖最新匹配：

```
时间线：
MESSAGE_RECEIVED 触发
  │
  ├── 立即：onMessageReceived()
  │     ├── chat-images: performMatch()（异步，捕获 gen）
  │     └── match-scoring: scoreMessages()（同步）
  │           └── import() 完成 → 主动插入 DOM  ← 通道 A
  │
  ├── (可能在这之间 DOM 渲染完成)
  │
  └── CHARACTER_MESSAGE_RENDERED 触发
        └── onAiMessageRendered()
              └── 检查 pendingResults → 补插 DOM  ← 通道 B

滑动时：
MESSAGE_SWIPED 触发
  └→ cancelPendingMatch() → _ciGeneration++ + 清除旧定时器
  └→ 文本变化 → onMessageReceived() → 新 performMatch()
      新 gen > 旧 gen → 旧 performMatch 完成时自动丢弃结果
```

## 二、状态缓存

```javascript
// 存储每个消息索引的最新文本，用于滑动时检测文本变化
window._mc_lastMesText = {};

// 挂起的结果：用于通道 B 补插
let pendingResults = null;

// 递增计数器，避免过时结果覆盖最新结果
let pendingGeneration = 0;

// chat-images generation 计数器（在 nav-chat-images/matcher.js 中）
let _ciGeneration = 0;
```


### 3.2 onMessageSwiped()

```
MESSAGE_SWIPED 触发
      │
      ▼
┌──────────────────────────────┐
│ 清除 pendingResults          │
│ 移除 DOM 中的 .mc-ms-chat-  │
│   results 和 .mc-ci-chat-    │
│   results                    │
│ 清除 scorer 的 lastResults   │
│ 清空结果面板                 │
│ cancelPendingMatch() → 递增  │
│   generation + 清除定时器    │
│ 清除聊天图片结果 DOM         │
└─────────┬────────────────────┘
          │
          ▼
┌──────────────────────────────┐
│ 比较文本是否变化             │
│ currentText vs _mc_lastMesText│
│ （首次滑动时 prevText 已     │
│   被 CHAT_LOADED 缓存）      │
└─────────┬────────────────────┘
          │ 文本变化了 (isNew)
          ▼
┌──────────────────────────────┐
│ 调用 onMessageReceived()     │
│ 重新匹配                     │
└──────────────────────────────┘
          │ 文本未变
          ▼
┌──────────────────────────────┐
│ 跳过重新匹配                 │
│（缓存回复，保留已有 DOM）    │
└──────────────────────────────┘
```

## 四、数据流示例

### 4.1 用户上传文件

```
用户点击上传按钮
      │
      ▼
file-events.js 检测点击
      │
      ▼
弹出文件选择对话框（浏览器原生 <input type="file">）
      │
      ▼
shared/file-service.js.uploadFile(file, { source, directory })
      │
      ├── 1. 生成唯一服务器文件名：MM_20260725_143015_123456.png
      │     (使用 generateServerFilename 函数)
      ├── 2. 读取文件为 base64
      ├── 3. 通过 SillyTavern API 上传到服务器
      │     POST /api/files/upload { name, data: base64 }
      ├── 4. 写入文件注册表
      │     addRegistryEntry({ id, serverFilename, originalName, ... })
      └── 5. 防抖保存 + 刷新 UI（renderFileManager）
```

### 4.2 聊天图片匹配并展示（chat-images）

```
AI 回复文本
      │
      ▼
shell/message-handler.js onMessageReceived()
      │
      ▼（异步 import）
nav-chat-images/matcher.js.performMatch(text)
      │ （捕获 _ciGeneration，异步完成时检查是否过期）
      ├── 1. 获取启用的规则列表
      ├── 2. 过滤启用的角色集 → 启用的规则集 → 按 order 排序
      ├── 3. 分两组：未分组规则 + 按规则集分组
      ├── 4. 遍历每条规则，执行 matchSingleRule(rule, text)
      │     ├── 编译正则（sanitizeRegex）
      │     ├── 正则测试
      │     ├── 匹配成功 → 查询注册表获取图片路径
      │     └── 加权随机选择图片
      ├── 5. 收集匹配结果（按规则集分组）
      ├── 6. 检查 gen !== _ciGeneration → 过期则丢弃（防滑动竞争）
      └── 7. 将结果渲染到聊天气泡（图片队列轮播）
```

### 4.3 匹配打分并展示（match-scoring）

```
AI 回复文本 + 用户提问文本
      │
      ▼
shell/message-handler.js onMessageReceived()
      │
      ▼（异步 import）
nav-match-scoring/scorer.js  →  scorer/scoring.js.scoreMessages(aiText, userText)
      │
      ├── 1. 获取所有启用的文件（注册表引用）
      ├── 2. 清洗文本（text.js.cleanText）
      ├── 3. 检测文本中的文件类型关键词（type.js.detectFileTypeKeywords）
      ├── 4. 为每个文件计算多维分数：
      │     ├── N-gram 分词匹配（ngram.js，单次扫描优化）
      │     ├── 标签匹配（tag.js，支持正则标签）
      │     ├── 文件类型匹配（type.js）
      │     ├── 关联词匹配（relation.js）
      │     ├── 字符模糊匹配（fuzzy.js）
      │     ├── 停用词匹配（stopwords.js）
      │     └── 类型偏好加权（type.js）
      ├── 5. 加权合成总分 + 密度归一化
      ├── 6. Fisher-Yates 同分洗牌 + 随机抖动
      ├── 7. 应用 Top-N + 最低分过滤
      │
      ▼
nav-match-scoring/match-chat-results.js（re-export hub）
      → match-chat-results/panel.js.renderResultsPanel()
      → match-chat-results/persist.js.persistChatResults()
      → match-chat-results/bubble.js.renderChatResults()
      │
      ├── renderResultsPanel(results) → 更新抽屉内的结果面板
      ├── persistChatResults(messageId, results) → 持久化到 chat.extra
      └── renderChatResults(messageId, results) → 按插位槽配置渲染到聊天气泡
            ├── 读取插位槽配置（slots[]）
            ├── 按类型分组（image/video/audio）
            ├── 按分数排序取 Top-N
            ├── 根据 carouselPlayCount / carouselShowCount 控制层级
            ├── 为每个插位渲染媒体元素
            └── 应用动画类型（@keyframes）
```

### 4.4 文件选择器交互流程

```
聊天图片/匹配打分需要选择文件
      │
      ▼
调用 showFilePickerPopup({ multiSelect, title })
      │
      ├── 1. 保存当前文件管理器状态
      ├── 2. 重置状态（根目录/清空选中）
      ├── 3. 设置活动渲染目标到弹窗内部
      ├── 4. 渲染文件管理器（含目录导航/排序/搜索）
      ├── 5. 绑定事件（确保弹窗内交互可用）
      ├── 6. 用户浏览/搜索/选择文件
      └── 7. 确认 → 恢复文件管理器状态 → 返回选中条目列表
            │
            ▼
      调用方获取选中条目的 registryId
            │
            ▼
      保存到规则图片列表 / 匹配打分文件列表
```
