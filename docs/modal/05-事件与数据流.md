# ModalChat 插件 — 事件与数据流

> 编写日期：2026年7月25日

## 一、SillyTavern 事件处理

| 事件 | 用途 | 处理模块 |
|------|------|---------|
| `CHARACTER_MESSAGE_RENDERED` | AI 消息渲染后触发匹配 | `nav-chat-images/matcher.js` + `nav-match-scoring/scorer.js` |
| `USER_MESSAGE_RENDERED` | 用户消息渲染后更新上下文 | `nav-match-scoring/scorer.js` |
| `MESSAGE_SWIPED` | 滑动切换回复 | 两者都需要重新处理 |
| `CHAT_CHANGED` | 切换聊天 | 清除缓存结果 |
| `CHAT_LOADED` | 聊天加载完成 | 恢复持久化结果 |
| `MESSAGE_DELETED` | 消息删除 | 重新计算 |

## 二、内部事件通信

模块间通过 SillyTavern 的 `eventSource` 进行通信：

| 事件名 | 触发者 | 监听者 | 用途 |
|--------|--------|--------|------|
| `modalChat:registryUpdated` | 文件管理器 | 聊天图片/匹配打分 | 注册表变化时刷新引用 |
| `modalChat:fileDeleted` | 文件管理器 | 所有模块 | 文件被删除时清理引用 |
| `modalChat:filesSelected` | 文件选择弹窗 | 调用方 | 返回选中的注册表 ID 列表 |

## 三、文件选择交互流程

```
聊天图片批量新增
      │
      ▼
打开文件选择弹窗（从文件管理器）
      │
      ▼
用户在弹窗中选择已有文件（复选框）
      │
      ▼
确认 → 返回选中文件的注册表 ID 列表
      │
      ▼
聊天图片模块：将注册表 ID 保存到规则图片列表
      │
      ▼
渲染规则界面（通过注册表 ID 查路径展示缩略图）
```

## 四、数据流示例

### 4.1 用户上传文件

```
用户拖拽文件到文件管理器
      │
      ▼
file-manager-ui.js 检测到文件
      │
      ▼
shared/file-service.js.uploadFile(file)
      │
      ├── 1. 生成唯一服务器文件名：MM_20260725_143015_123456.png
      ├── 2. 通过 SillyTavern API 上传到服务器
      │     POST /api/files/upload { name, data }
      ├── 3. 写入文件注册表
      │     fileRegistry.push({ id, serverFilename, originalName, ... })
      └── 4. 保存设置 + 刷新 UI
```

### 4.2 聊天图片匹配并展示

```
AI 回复文本
      │
      ▼
nav-chat-images/matcher.js.performMatch(text)
      │
      ├── 1. 获取启用的规则
      ├── 2. 遍历规则，正则匹配
      ├── 3. 匹配成功 → 从规则图片中获取 registryId
      ├── 4. 通过 registryId 查文件注册表 → 获取文件路径
      └── 5. 渲染图片到聊天气泡
```

### 4.3 匹配打分并展示

```
AI 回复文本
      │
      ▼
nav-match-scoring/scorer.js.scoreMessages(aiText, userText)
      │
      ├── 1. 遍历文件（注册表引用）
      ├── 2. 计算各维度分数
      ├── 3. 加权合成总分
      ├── 4. 按分数排序 + 随机抖动
      └── 5. 渲染 Top-N 结果到聊天气泡
         └── 渲染时通过注册表 ID 查文件路径
```
