# ModalChat 插件 — 文件管理器设计

> 编写日期：2026年7月25日 | 最后更新：2026年7月27日

## 一、概述

文件管理器是 ModalChat 新增的核心功能，统一管理所有媒体文件的上传、删除、移动、重命名和目录组织。它由 7 个子模块组成，职责分离清晰。

## 二、模块架构

```
nav-file-manager/
├── index.js                # 薄导入层（重新导出公开接口）
├── file-render.js          # ★ 渲染引擎（目录树/文件列表/面包屑/分页/加载态）
├── file-events.js          # ★ 事件引擎（事件委托，所有交互处理）
├── file-state.js           # ★ 状态管理（模块级变量，无 UI 依赖）
├── file-url.js             # URL 解析（注册表 → 可访问 URL）
├── file-picker-popup.js    # 文件选择器弹窗（供聊天图片/匹配打分调用）
├── file-manager-ui.js      # 重新导出 hub（保持向后兼容）
└── file-registry.js        # 注册表查询（搜索/类型/来源过滤）
```

### 2.1 各子模块职责

| 文件 | 职责 | 导出 |
|------|------|------|
| `file-state.js` | 所有模块级状态变量：当前目录、选中集合、分页、排序、搜索模式。**无 DOM 依赖**，可被事件/渲染/弹窗等模块共享 | `currentDir`, `selectedFiles`, `fmCurrentPage`, `fmSortBy`, `fmSortDesc`, `fmViewMode`, `fmSearchMode`, `fmSearchTriggered` + 对应的 setter 函数 |
| `file-render.js` | 异步渲染文件管理器 UI，含加载态显示、目录树构建、文件列表渲染、面包屑导航、分页栏、两种视图模式（`simple`/`detail`）。支持活动渲染目标（`setActiveFileManagerTarget`），可用于弹窗内渲染 | `renderFileManager(target?)`, `setActiveFileManagerTarget(selector)` |
| `file-events.js` | 使用事件委托（`$(document).on`...）为所有 UI 元素绑定交互：目录导航、上传、新建目录、删除文件、重命名、批量操作、筛选、排序、文件详情弹窗、全屏查看等 | `bindManagerEvents()`, `enterSelectionMode()` |
| `file-url.js` | 根据注册表条目或 ID 获取可访问的服务端 URL，处理路径前缀 | `getFileUrl(entryOrId)` |
| `file-picker-popup.js` | 弹出与文件管理器界面一模一样的弹窗，供聊天图片和匹配打分模块选择已有文件。保存/恢复文件管理器状态 | `showFilePickerPopup(options)` |
| `file-manager-ui.js` | 仅重新导出，不做任何逻辑处理 | 重新导出 |
| `file-registry.js` | 注册表查询辅助功能（搜索、类型列表、来源列表） | `searchRegistry`, `getAllTypes`, `getAllSources` |

## 三、核心概念

### 3.1 文件注册表（File Registry）

文件注册表是一个中央索引，维护所有文件的元数据与实际存储位置的映射：

```javascript
// 文件注册表条目
{
  id: 'reg_a1b2c3d4',                      // 注册表唯一 ID
  source: 'chat-images',                    // 来源: 'chat-images' | 'match-scoring' | 'file-manager'
  serverFilename: 'ChatImages_20260725_143015_123456.png',  // 服务端存储的真实文件名
  originalName: '我的照片.jpg',             // 用户上传时的原始文件名
  displayName: '海边日落',                   // 用户自定义展示名
  type: 'image',                            // 'image' | 'video' | 'audio'
  mimeType: 'image/png',
  relativePath: 'my-folder/',               // 相对于 files 根目录的路径（含尾部 /）
  fullServerPath: 'user/files/my-folder/ChatImages_20260725_143015_123456.png',
  fileSize: 1024000,
  uploadDate: 1718000000000,
  directory: '/my-folder/',                 // 所属目录
}
```

### 3.2 服务端真实文件名格式

```
{来源前缀}{日期}_{时间}_{6位随机数}.{扩展名}
```

| 来源 | 前缀 | 示例 |
|------|------|------|
| chat-images | `ChatImages_` | `ChatImages_20260725_143015_123456.png` |
| MatchScoring | `MatchScoring_` | `MatchScoring_20260725_143015_123456.jpg` |
| 文件管理器新上传 | `MM_` | `MM_20260725_143015_654321.webp` |

### 3.3 存储根目录

所有文件存储在 SillyTavern 的 `/user/files/` 路径下。

### 3.4 海量数据支持

注册表 **按目录分文件存储**（每个目录一个 JSON 文件），只有访问到的目录才加载到内存：

```
/user/files/
├── ModalChat_settings.json          # 全局设置
├── ModalChat_chat-images_data.json  # 聊天图片数据
├── ModalChat_match-scoring_data.json# 匹配打分数据
├── ModalChat_reg-index.json         # 轻量索引 { id → directory }
├── ModalChat_dir_abc123.json        # 根目录注册表条目
├── ModalChat_dir_def456.json        # 子目录注册表条目
└── ...
```

- **轻量索引**（约 50 字节/条）始终在内存中
- **完整条目**只按需加载到 `_entryCache`（Map）
- 支持 5 万+ 条注册表条目

### 3.5 目录结构

目录是**虚拟的文件系统目录**，支持：
- 创建目录（在 `files` 根目录下创建逻辑子文件夹）
- 删除目录（递归删除所有子目录/文件）
- 重命名目录（更新所有受影响条目的 directory 字段）
- 目录树浏览（面包屑导航）

### 4.1 视图模式

| 模式 | 描述 | 用途 |
|------|------|------|
| `detail` | 文件列表模式，显示文件名/类型/大小/日期/操作按钮 | 默认模式，适合管理 |
| `simple` | 精简列表模式，仅显示复选框 + 图标 + 名称 + 大小 | 嵌入弹窗时使用，空间高效 |

## 五、状态管理

文件管理器使用纯模块级变量（`file-state.js`）管理所有 UI 状态：

```javascript
// 核心状态变量
currentDir      = '/'                    // 当前浏览目录
selectedFiles   = new Set()              // 选中的注册表 ID 集合
fmCurrentPage   = 1                      // 当前页码
fmSortBy        = 'uploadDate'           // 排序字段
fmSortDesc      = true                   // 是否降序
fmViewMode      = 'detail'               // 视图模式: 'detail' | 'simple'
fmSearchMode    = 'simple'               // 搜索模式: 'simple' | 'full'
fmSearchTriggered = false                // 搜索触发标志
FM_PAGE_SIZE    = 50                     // 每页文件数
```

## 六、操作列表

| 操作 | 触发 | 实现函数 | 说明 |
|------|------|---------|------|
| 上传文件 | 点击上传按钮 | `file-service.uploadFile()` | 支持多文件，上传到当前目录 |
| 删除文件 | 点击删除按钮 | `file-service.deleteFile()` | 同时删除服务端文件和注册表条目 |
| 重命名文件 | 文件详情弹窗 → 重命名 | `file-service.renameFile()` | 只改展示名，服务端文件名不变 |
| 创建目录 | 点击新建目录按钮 | `file-service.createDirectory()` | 创建虚拟目录 + 数据文件 |
| 删除目录 | 目录详情弹窗 → 删除 | `file-service.deleteDirectory()` | 递归删除子目录和所有文件 |
| 重命名目录 | 目录详情弹窗 → 重命名 | `data.js renameDirectory()` | 更新所有受影响的注册表条目的 directory 字段 |
| 搜索文件 | 输入搜索关键词 + 确认 | `data.js searchRegistry()` | 支持简单搜索（当前目录）和全文搜索（所有子目录） |
| 排序 | 点击排序下拉菜单 | 按 displayName/fileSize/uploadDate/type 排序 | 升降序切换 |
| 分页 | 点击分页按钮 | 每页 50 条 | 页码自动修正 |
| 全选/反选 | 点击全选按钮 | `selectedFiles` Set 操作 | 批量操作前使用 |

## 八、与其他模块的交互

### 8.1 聊天图片（nav-chat-images）

- **新增规则图片**：调用 `showFilePickerPopup()` → 用户勾选已有文件 → 保存注册表 ID 到规则 `images[{ registryId, weight }]`
- **展示图片**：`getRegistryById(registryId)` → `getFileUrl(entry)` → 渲染 `<img>`
- **删除规则图片**：仅移除规则中的 registryId 引用，不删实际文件

### 8.2 匹配打分（nav-match-scoring）

- **添加匹配文件**：调用 `showFilePickerPopup()` 或使用批量新增弹窗 → 注册到 `navMatchScoring.files[]`
- **展示匹配结果**：通过 `getRegistryById()` 查路径 → 按插位槽配置渲染到聊天气泡
- **批量新增**：`popup-batch.js` 调用 `showFilePickerPopup()` + 设置共用名称/标签/内容
